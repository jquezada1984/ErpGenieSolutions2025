================================================================================
1. RESUMEN EJECUTIVO
================================================================================

No existe una pantalla funcional de “Stock actual” dentro de Almacenes.

Sí existen dos pantallas de stock bajo Productos:
  - /items/productos/stocks
  - /items/productos/stocks-lotes

Ambas son MOCK: declaran explícitamente datos de ejemplo, no consultan saldo
real, no consumen stockItemsAlmacenListado y contienen acciones locales que no
son apropiadas para una futura pantalla read-only.

La ubicación correcta para una futura pantalla es una VISTA NUEVA bajo el
dominio Almacenes:
  Almacenes → Stock actual → /items/almacenes/stock-actual

No corresponde reutilizar “Cambio masivo de stock” ni “Stock por fecha”:
ambas opciones están definidas en el SQL de menú, pero sus rutas no existen en
Router.tsx ni sus vistas en frontReact. Son RUTAS HUÉRFANAS.

La query ya disponible permite implementar la futura pantalla sin tocar
Inventarios, AlmacenPython, el motor de escritura, Gateway ni backend:
  stockItemsAlmacenListado(id_empresa!, id_almacen?, id_item?, estado?)

Propósito visual:

  toggle de estado exclusivamente sobre state local mock.

Paginación/UI:
  ReactTable, paginación local, Card/Alert/Badge/SelectEmpresa.

Clasificación:
  MOCK. Es reutilizable solo como REFERENCIA VISUAL parcial, no como fuente

13. OPCIONES DE UBICACIÓN
================================================================================

OPCIÓN A — Reutilizar una ruta/pantalla existente
  Candidata: /items/productos/stocks.
  Ventaja: ya tiene tabla, filtros, selector de empresa y apariencia similar.
  Riesgos: usa mock, se ubica en Productos, no discrimina almacén como entidad
  principal, incluye acciones locales y columnas comerciales ajenas.
  Impacto: requeriría reescritura considerable y mezclaría responsabilidades.
  No recomendada.

OPCIÓN B — Reutilizar visualmente ProductosStocks, creando una vista nueva
  Ventaja: aprovecha referencia de columnas/ReactTable/estilo.
  Riesgos: copiar acciones mock o semántica de stock límite/comercial.
  Impacto: medio. Reutilizar solo patrón visual, no código de datos/acciones.
  Parcialmente válida como guía de diseño.

OPCIÓN C — Crear posteriormente “Almacenes → Stock actual”
  Ruta propuesta: /items/almacenes/stock-actual.
  Ventajas: separa saldo actual de productos, movimientos e inventarios;
  refleja el dominio de stock por almacén; usa el contrato ya disponible;
  permite una pantalla estrictamente read-only.
  Riesgos: requiere nueva vista, ruta y entrada de menú/permisos.
  Impacto: acotado a frontend/menu de Almacenes; no necesita backend adicional.
  RECOMENDADA.

OPCIÓN D — Reutilizar “Cambio masivo de stock” o “Stock por fecha”
  Ventaja: existen nombres de menú declarados.
  Riesgos: ambas rutas son huérfanas; cambio masivo sugiere escritura y stock
  por fecha requiere histórico inexistente.
  Impacto: semántica incorrecta y riesgo de ampliar alcance.
  No recomendada.
