3. ARQUITECTURA REAL
======================================================================

ESCRITURA STOCK + CABECERA (REST):
  Frontend → Gateway → AlmacenPython:3018 → PostgreSQL

ESCRITURA ESTADO ALMACÉN:
  Frontend → Gateway GraphQL → AlmacenNestJs:3017 → UPDATE almacen.estado

LECTURA (listados, stock, movimientos):
  Frontend → Gateway GraphQL → AlmacenNestJs → SELECT

IDENTIDAD STOCK (fail-closed):
  Gateway authenticatedWriteContext → InicioNestJs query `me`

IDENTIDAD CRUD ALMACÉN:
  Gateway ctxHeaders → InicioNestJs query `usuario(id_usuario)` (no fail-closed)

JWT en Python inicializado (Flask-JWT-Extended) pero no enforced en rutas;
confía en gateway + headers propagados.

4. WRITERS DE STOCK
======================================================================

Writer        | Endpoint Python              | FOR UPDATE | Invariante      | Índice idempotencia
--------------|------------------------------|------------|-----------------|---------------------------
Inicial       | POST /api/almacen/stock-inicial    | No         | N/A (nuevo)     | uq_mov_inv_stock_inicial_idempotencia
Entrada       | POST /api/almacen/stock-entrada    | Sí         | Antes/después   | uq_mov_inv_entrada_stock_idempotencia
Salida        | POST /api/almacen/stock-salida     | Sí         | + disp >= Q     | uq_mov_inv_salida_stock_idempotencia
Ajuste        | POST /api/almacen/stock-ajuste     | Sí         | ± según tipo    | uq_mov_inv_ajuste_stock_idempotencia
Transferencia | POST /api/almacen/stock-transferencia | Sí (par) | Origen+destino | uq_mov_inv_transferencia_stock_idempotencia

Patrón común: transacción única, replay por id_origen, rollback completo.
Costos: precio_compra del item o 0 (persistencia básica, sin Kardex).
Ajuste NO reutiliza tipos ENTRADA/SALIDA.

Stock writers en Python validan:
  - X-Company-Id obligatorio
  - body.id_empresa == header X-Company-Id

5. TRANSFERENCIA
