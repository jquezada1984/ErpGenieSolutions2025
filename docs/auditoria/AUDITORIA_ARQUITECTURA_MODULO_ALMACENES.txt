2. INVENTARIONESTJS
--------------------------------------------------------------------------------

Entrada: src/main.ts
  - NestFactory.create(AppModule)
  - Puerto: process.env.PORT ?? 3011
    NOTA: default en código es 3011; en docker-compose el servicio usa PORT=3013.
    CONFIRMADO POR CONFIGURACIÓN docker: 3013.

AppModule:
  - GraphQLModule (ApolloDriver, autoSchemaFile schema.gql, playground/introspection)
  - TypeOrmModule.forRoot: postgres, DATABASE_URL, synchronize:false
  - InventarioModule

Módulo interno: InventarioModule
  - TypeOrmModule.forFeature([Inventario])
  - InventarioService, InventarioResolver

Entity: Inventario → tabla "inventario"
  Columnas mapeadas: id_inventario, id_empresa, inventario_ref, etiqueta,
  id_almacen, estado_inventario, fecha_inicio/cierre, observacion,
  created_by/updated_by, created_at/updated_at, estado (boolean)

Objects GraphQL:
  - InventarioListado
  - InventarioDetalle (cabecera para edición; NO es tabla inventario_detalle)

Resolvers / operaciones:
  Query inventariosListado (filtros id_empresa, ref, etiqueta, warehouse, id_almacen, product, estado_inventario)
  Query inventarioPorId
  Mutation actualizarEstadoInventario(id_inventario, estado: Boolean)

Auth: NO hay AuthGuard/JwtStrategy en InventarioNestJs (CONFIRMADO: sin coincidencias).
Headers: Nest no exige headers en código; Gateway reenvía Authorization, X-Company-Id, X-User-Id al proxy GraphQL.
id_empresa: filtro opcional en queries; no valida JWT internamente.
created_by/updated_by: en entity; la mutación de estado solo setea estado + updated_at (no updated_by en Nest).

Health: no hay /health en Nest (solo log de arranque GraphQL).

FLUJO LECTURA:
  Front Apollo → Gateway POST /graphql
    → getTargetService detecta inventariosListado | inventarioPorId | actualizarEstadoInventario
    → INVENTARIO_NEST_GQL_URL (inventario-nestjs-service:3013)
    → InventarioResolver/Service → PostgreSQL tabla inventario (+ JOIN almacen para nombre)

3. INVENTARIOPYTHON
--------------------------------------------------------------------------------

Framework: Flask + flask_cors + flask_jwt_extended + SQLAlchemy + Marshmallow
Entrada: app.py
  - Blueprint inventario_bp prefix /api
  - GET /health → {status: ok}
  - JWTManager configurado; rutas de inventario NO usan @jwt_required (leen headers)

Config: DATABASE_URL, SECRET_KEY, CORS_ORIGINS
Puerto: env PORT; docker 3014; fallback código __main__ 3012 (distinto al compose)

Routes (api/inventario_routes.py):
  POST   /api/inventario          crear
  PUT    /api/inventario/<uuid>   actualizar cabecera
  PATCH  /api/inventario/estado   actualizar estado boolean
  OPTIONS en todas

Headers: X-Company-Id / X-User-Id → id_empresa (body o header), user_id auditoría
Schemas Marshmallow: InventarioCreateSchema, InventarioUpdateSchema, InventarioEstadoUpdateSchema
Service: validación, duplicado inventario_ref+empresa, defaults estado_inventario=ABIERTO
Repository: create/update commit/rollback
Respuestas: { success, message, data } o errors/error; HTTP 201/200/400/404/409/500

FLUJO ESCRITURA:
  Front axios (_apis_/inventario.js) → Gateway /api/inventario
    → inventarioPython.js (ctxHeaders + Authorization)
    → InventarioPython /api/inventario
    → PostgreSQL tabla inventario

8. ITEM COMO COMPARACIÓN
--------------------------------------------------------------------------------

IGUAL:
  Nest lectura GraphQL + Python escritura REST
  Gateway enruta por nombre de query / rutas /api/item vs /api/inventario
  Docker pares de puertos

  ItemNestJs: más módulos (catálogos), entity Item parcial vs detalle raw

  Inventario: dominio más pequeño (cabecera inventario)
  Toggle estado Item: mutation en ItemNestJs; Inventario similar en Nest
  Front Item: más secciones/formularios; Inventario más simple
